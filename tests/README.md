# テスト

アプリ本体は単一の `index.html`（ビルド無しのバニラJS）です。
ここには開発時の動作検証（ヘッドレスブラウザによるE2E）を置いています。
GitHub Pages で配信される本体には影響しません。

## 実行

```sh
npm i -D playwright
node tests/e2e.mjs
```

## 検証内容（`e2e.mjs`）

- 会計の記録（客数・合計・お釣り）
- 超過販売（仕入数より多く売れた場合に在庫がマイナスになり、レポートに警告として検出される）
- 会計済の部分修正（品目±が 売上・在庫・編集フラグ・操作ログ に反映される）
- 会計取消（客数・在庫・売上・取消件数 に反映される）
- データ整合性（品目合計＝取引合計）
- レポート（全7セクションの生成）
- 味タグのマスタ化（外部辞書の読込と、商品ごとの明示タグ優先）
- 閉店時アーカイブ（商品別実績を保存し次回比較のベースラインにする）
- 取扱商品の選択（この回で販売しない商品はグリッド対象外）
- 残りわずか/完売アラート（在庫がしきい値に到達した瞬間の通知）
- 原価入力時の粗利集計（一部未入力なら対象品のみの部分集計）
- 前回販売会との比較（総売上・客数・客単価・商品別の増減）
- 取りこぼし推定・併売セット提案のヘルパ
- 精算CSVの拡充（消化率・完売時刻・原価・粗利・味の列）

## 置き場の決まりの試験（`rules/`）

`firestore.rules`（Firebase の置き場の決まり）を、Firestore エミュレーターで本物と同じに当てて、
ほかのお店の端末・お客様・外された端末が「できてはいけないこと」を断るか、ふだんの使い方が通るかを確かめます（105項目）。
Java（エミュレーターが使う）が要ります。

```sh
cd tests/rules
npm i
npm test
```

決まりを書きかえたら、必ずこの試験を通してから公開してください。

## 予約帳の通しの試験（`rules/yoyaku.e2e.mjs`）

予約帳（`yoyaku.html`・`yoyaku-kanri.html`）を、エミュレーターに本物の `firestore.rules` を当てて、ブラウザで通しで動かします（35項目）。
予約できる・受け取り・取り消し・記録・店頭の予約・数え直し・控えのファイル・CSV・鍵で別の端末から管理者になる・
何度押しても1件・同時に予約しても上限と番号が正しい・送れたか分からない時の送り直し・電波なし・受付の外・文字の混入 を確かめます。

```sh
cd tests/rules
npm i && npm i -D playwright
npm run test:yoyaku
```

## すべての画面を開く試験（`screens.e2e.mjs`）

店舗モード（既製品・ファストフード・レストラン）× 言葉（日本語・英語）× 大きさ（スマホ・タブレット横）で、「レジの機能」を全部オンにし、
閉店の時と営業中の時に、すべての画面（設定の中の画面・集計の項目も）を開きます。エラーが出ない・横にはみ出さない・押せる物が小さすぎない、を確かめます。

```sh
node tests/screens.e2e.mjs            # 全部（時間がかかります）
ONLY=retail/ja/phone node tests/screens.e2e.mjs
```

## お金の流れの乱れ打ち（`money.fuzz.mjs`）

カートに入れる・減らす・値引き・支払い方法・分けて会計・予約・受け取り・取り消し・会計の後の直し・割引を外す を、でたらめな順で続け、
1回ごとに「品目の合計 − 割引 ＋ 外税 ＝ 取引の合計」「お預かり・お釣り」「在庫」「客No. が重ならない」を確かめます。

```sh
node tests/money.fuzz.mjs 500 1      # 回数・乱数の種
TAX=ex node tests/money.fuzz.mjs     # 税抜きの値段（外税）で
```

## レジ2台の共有の試験（`rules/sync.e2e.mjs`）

エミュレーターで、2台目が合言葉で合流し、両方で会計・取り消し・品目の直し・電波が切れた間の会計を行って、
両方の端末と置き場で、件数・合計・在庫が合うか（消えない・二重にならない）を確かめます。

```sh
cd tests/rules && npm run test:sync
```
