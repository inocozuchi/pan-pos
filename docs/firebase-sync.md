# 複数端末リアルタイム同期（Cloud Firestore）ガイド

このアプリは、**設定を入れたときだけ**複数端末で売上をリアルタイム共有できます。
設定が空、または通信できないときは、**従来どおり各端末の中だけで安全に動作**します（オフラインでも会計は止まりません）。

---

## 1. できること
- 同じ「**共有コード**」を入れた端末どうしで、**会計・取消・修正・客属性・在庫（残数）をリアルタイム共有**。
- 2台以上で**同時に会計**しても、売上を1つのリストに統合。集計・レポートも全端末分をまとめて計算。
- 在庫は「仕入れ数 − 全端末の販売数合計」で表示（売り越しに全端末で気づける）。

## 2. 有効化の手順（コンソール作業が済んだら）
Firebaseコンソール側（プロジェクト作成／Firestore作成／匿名認証ON／`firebaseConfig`取得／ルール公開）が完了している前提です。

1. `data/firebase-config.js` を開く。
2. 末尾の `window.FIREBASE_CONFIG = null;` を、コンソールでコピーした設定に置き換える：
   ```js
   window.FIREBASE_CONFIG = {
     apiKey: "…",
     authDomain: "…",
     projectId: "…",
     storageBucket: "…",
     messagingSenderId: "…",
     appId: "…"
   };
   ```
3. GitHubにコミット＆Push（GitHub Pagesに反映）。
4. アプリを開くと「開店・設定」に **🔗 複数端末で同時に会計する** の欄が出ます。

> Web用APIキーは公開前提の識別子なので、貼り付けても問題ありません。
> データ保護は下の「セキュリティルール（匿名認証必須）」で行います。

## 3. セキュリティルール（Firestore →「ルール」に貼る）
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // 販売会(events)配下は「ログイン(匿名認証)済み」のみ読み書き可
    match /events/{eventCode}/{document=**} {
      allow read, write: if request.auth != null;
    }
  }
}
```
- これで「未認証の直アクセス」は弾けます。
- さらに厳密にするなら、共有コードを**推測されにくい文字列**にする／後日 **App Check** を追加、を推奨します（完全会員制ではない点はご理解ください）。

## 4. 当日の使い方

### 仕組みの前提（重要）
- 同じ共有コードで**最初に「開店」した端末が「作成」**となり、その端末で設定した商品名・価格・仕入れ数が、この販売会の**共有の商品構成**になります。
- 同じコードで**あとから「開店」した端末は自動的に「参加」**になります。参加する端末で仕入れ設定画面に何を入力していても使われません（共有中の商品構成にそのまま揃います）。参加時は確認ダイアログが出ます。
- 「閉店する（集計して終了）」は**共有販売会そのものを終了する操作**です。同じコードで別の端末がまだ使っている場合は、先にそちらへ声をかけてから閉店してください。
- 一時的にこの端末だけ操作をやめたい場合は「🚪 この端末の利用を終える（他の端末は継続）」を使ってください。共有販売会は終了せず、他の端末はそのまま続けられます。

### ケースA：ピーク時だけ2台体制にする
1. 通常運用の端末（端末1）で、共有コード（例 `pansale-1101`）を入力して開店（＝作成）。
2. 混雑してきたら、応援の端末（端末2）で**同じコード**を入力して開店 → 「参加しますか？」で「OK」。
3. 2台で同時に会計。売上・在庫はリアルタイムで両方に反映されます。
4. 落ち着いたら、端末2で「🚪 この端末の利用を終える」。共有販売会は端末1でそのまま継続します。
5. 最終的に端末1で「閉店する（集計して終了）」。

### ケースB：午前・午後で別の人のスマホに交代
1. 午前担当が自分のスマホ（端末1）で共有コードを入力して開店（＝作成）。
2. 午前が終わったら、端末1は「🚪 この端末の利用を終える」（閉店ボタンは押さない）。または単にアプリを閉じるだけでも他端末には影響しません。
3. 午後担当が自分のスマホ（端末2）で**同じコード**を入力して開店 → 「参加しますか？」で「OK」（午前分の売上・残在庫がそのまま引き継がれます）。
4. 午後の営業終了時、端末2で「閉店する（集計して終了）」。これで共有販売会全体の集計が確定します。
5. もし端末1がまだ「営業中」表示のまま残っていても、実害はありません（データは既に確定済み）。気になる場合は端末1を開いて状況を確認し、必要なら改めて「🚪 この端末の利用を終える」を押してください。

### 時間差で開店した場合の同期
- 端末1が先に開店し、数時間後に端末2が同じコードで開店（参加）しても、**それまでの売上・在庫はすべて引き継がれます**（Firestoreは購読開始時に既存の全データを送ってくるため）。

### 同じコードを閉店後に使い回した場合
- 一度「閉店する」で終了したコードを別の販売会で再利用しようとすると、**「このコードは閉店済みです」と警告が出ます**。誤って前回のデータと混ざらないよう、[OK]を選ぶと自動で新しいコードが作られて開店します。

## 5. オフライン時の動作
- 通信が切れても会計は続行できます（端末内キャッシュに保存）。
- **回線が戻ると自動でまとめて同期**されます。
- 同期が一度も繋がらない端末は、その端末単独の売上として動きます（データは消えません）。

## 6. 客No.・在庫の注意
- 客No.は**全端末の会計を時刻順につなげた通し番号**です（重複しません）。会計履歴には、どの端末で記録したかが `［DA］` のようなラベルで併記されます。
- ごく僅かなタイミングのずれで、極めて短時間に複数端末でほぼ同時に会計した場合、通信状況によって客No.の順番が後から1つ入れ替わることがあります（金額・件数には影響しません）。
- 在庫はカート投入時点では減らず、**会計確定時**に全端末へ反映されます（複数端末では取り置き予約はできないため）。同期中の在庫は「共有の仕入れ数 − 全端末の合計販売数」で計算されます。

## 7. 同期をやめたい / 1台運用に戻す
- `data/firebase-config.js` を `window.FIREBASE_CONFIG = null;` に戻してPush。
- それだけで従来の1台運用（localStorage）に戻ります。データ構造は共通なのでバックアップ/引き継ぎ機能はそのまま使えます。

## 8. 実機での確認チェックリスト（重要）
本番のFirebase接続は開発環境ではテストできないため、公開後に以下をご確認ください。
- [ ] 2台で同じコードを開き、片方の会計が数秒でもう片方に出る。
- [ ] 客No.が2台の会計を通して重複しない（1,2,3…と続く）。
- [ ] 取消・品目修正・客属性入力が両端末に反映される。
- [ ] 在庫（残数）が両端末の販売を合算して減る。
- [ ] 1台を機内モードにして会計 → 復帰後にもう1台へ同期される。
- [ ] 端末2で後から同じコードを開店 →「参加しますか？」の確認が出て、参加すると端末1の売上・在庫を引き継ぐ。
- [ ] 端末2で「🚪 この端末の利用を終える」→ 端末1はそのまま継続できる。
- [ ] 端末1で「閉店する（集計して終了）」→ 集計・レポート・CSVが全端末分の合計になっている。
- [ ] 閉店済みのコードで再度「開店」しようとすると警告が出る。

## 9. 費用
- 無料枠（Sparkプラン）で十分です（学内販売会の件数なら余裕。クレジットカード登録も不要）。
